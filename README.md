# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 盾构机设备档案：单一取数与业务规则

盾构机的列表、导出、退场打包、看板统计只准读同一份设备档案（`src/data/shield-domain.ts`
里的 `selectShieldArchive`），不存在「页面一份、导出一份」。围绕这份档案的规则：

- **存量对账（一次性、幂等）**：首次读取时把旧台账、下载件、补录件按盾构机编号合并；同号重复
  行只记一台（`来源行` 保留并入的旧 id），补录过进场日期的以补录件为准，状态取流转中最靠后的，
  缺失字段互相补齐。结果与结构版本号在同一事务里提交。
- **维保单位一种写法**：简称/俗称（如「中铁装备技服」）统一归一到工商全称；不认识的写法原样
  保留，不做臆测归并。
- **进场日期统一算法**：以档案「进场日期」为准，兼容 `2026/3/5`、`2026年3月5日`、`2026.3.5`、
  带时间串等存量写法，统一存 `yyyy-MM-dd`；非法日历日期（如 2 月 30 日）拒绝并退回。
- **退场结论与掘进环次待办对齐**：该设备名下还有「待掘进/掘进中」环次时，退场被挡回并列出环号；
  未挂到任何设备的待办环不卡退场，只在页面提示。结论由域层核算，页面无法篡改。
- **封存与权限**：已退场设备不许再改开挖直径；只有「设备管理员」角色可改，值班员越权提交一律
  挡回（页头可切换角色演练）。
- **退场 + 补录同一事务**：`submitExitWithBackfill` 两边都过才提交，任一边写不成就整笔退回，
  不留半条。同一动作重复提交幂等，只记一次。
- **断点续导**：导出/打包按台分批、每台一个检查点（`src/data/export-pipeline.ts`）；中断后从
  断掉那台接着打，未完成不产出文件；资料包（`.stpkg`）含档案 CSV、环次对齐表与校验清单，
  三处台数一致才封口。
